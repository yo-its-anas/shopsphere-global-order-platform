# ShopSphere Google Cloud PoC Terraform Baseline

This root module is an **import-first baseline** for the existing ShopSphere Google Cloud VM and its supporting VPC, subnet, static IP, and narrowly scoped firewall rules. It is designed for formatting, validation, planning, drift review, and optional import. It must not be applied until every planned change has been reviewed and explicitly approved.

Terraform does not create service accounts or service-account keys here. Credentials must come from an approved local identity mechanism such as Application Default Credentials or workload identity and must never be committed.

## Scope and safeguards

The declared PoC shape is one Ubuntu 22.04 LTS `n2-standard-8` VM with an approximately 300 GiB balanced persistent boot disk and a reserved regional external IP. It includes:

- custom-mode VPC and private subnet;
- SSH restricted to one required, explicitly supplied IPv4 CIDR;
- HTTP/HTTPS firewall preparation disabled by default and controlled by explicit source CIDRs;
- no public firewall rules for PostgreSQL, Redis, Kafka, Keycloak administration, Jenkins, Kubernetes administration, or observability administration;
- mandatory `environment=poc`, `project=shopsphere`, and `managed_by=terraform` labels;
- Compute Engine deletion protection, Terraform `prevent_destroy`, and `auto_delete = false` for the boot disk;
- no startup script, secrets, embedded project ID, credential, or IP address.

`prevent_destroy` is an important guard, not a substitute for plan review, IAM restrictions, state backup, disk snapshots, or GCP deletion protection. Removing a resource block also removes its lifecycle rule from configuration; always inspect the plan.

## PoC versus production

This module describes the implemented target constraint: one Ubuntu VM running Docker and a single-node kind cluster. It does not provide production availability or isolation. The recommended future architecture is a separately designed regional GKE platform with multiple zones, managed data services, private networking, workload identity, autoscaling, backup and recovery, and enterprise security controls. Do not evolve this root module into production by merely increasing VM size.

## Prerequisites

- Terraform CLI compatible with `versions.tf`.
- Google Cloud APIs and an authenticated operator identity with only the permissions needed to inspect or import the named resources.
- Exact existing resource names, location, subnet CIDR, VM configuration, firewall behavior, and static address reservation.
- An approved Terraform state location. Local state is acceptable only for initial offline validation and contains infrastructure data that must not be committed.

No key file is required or generated by this repository.

## Configure safely

1. Copy `terraform.tfvars.example` to ignored `terraform.tfvars`.
2. Replace all placeholders with verified existing-resource values.
3. Keep `enable_public_web_ingress = false` until HTTP/HTTPS exposure has explicit approval.
4. Review OS Login, service-account, Shielded VM, labels, tags, disk, and network settings against the existing VM before import. Differences can produce update or replacement actions.
5. Follow [import-existing-resources.md](import-existing-resources.md) before treating existing infrastructure as managed.

## Validation-only workflow

The following commands do not apply infrastructure:

```bash
terraform fmt -check -recursive
terraform init -backend=false
terraform validate
terraform plan -out=shopsphere-poc.tfplan
terraform show shopsphere-poc.tfplan
```

The generated plan can contain project topology and must remain local; `*.tfplan` and Terraform state are ignored. A plan proposing replacement or deletion of the existing VM, disk, address, network, or subnet must be rejected and investigated.

For a first plan against existing resources, import them into an approved state by following the import guide. Planning without importing declared existing resources will propose creating them and is not proof that creation is safe.

## Public ingress policy

SSH has no default CIDR and rejects `0.0.0.0/0`. Web ingress has no default sources and is disabled. Enabling web ingress creates only TCP 80 and 443 access for `web_source_cidrs`. Jenkins and internal data-service ports are deliberately absent; access them through private networking or an approved administrative tunnel, never a public firewall rule.

## Files

- `network.tf`: protected PoC VPC, subnet, and regional address.
- `firewall.tf`: restricted SSH and optional controlled web ingress only.
- `compute.tf`: protected existing-VM desired configuration.
- `variables.tf` and `locals.tf`: validated inputs and enterprise labels/naming.
- `backend.tf.example`: opt-in remote-state template with placeholders.
- `import-existing-resources.md`: cautious import and reconciliation runbook.
