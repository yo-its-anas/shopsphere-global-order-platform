# Requirements Traceability Matrix

This matrix maps examination requirements to capability ownership, planned components, evidence, and current status. `Foundation established` means only that repository locations or governance documents exist. `Planned` means no implementation or execution evidence currently exists.

## Status definitions

- **Foundation established** — a documented repository boundary exists, but the capability is not implemented.
- **Planned** — no implementation evidence exists yet.
- **Implemented** — reserved for working source or configuration present in the repository and supported by evidence.
- **Verified** — reserved for executed tests or validation with retained evidence.

## Current evidence boundary

The repository contains independently buildable services, implemented customer profile/address/account/audit and normalized activity APIs with isolated PostgreSQL test evidence, a mock-data frontend, baseline Terraform and Kubernetes configuration, deployed PoC PostgreSQL and Keycloak foundations with validation automation, a Jenkins validation pipeline, governance files, ADRs, and this traceability model. It does not prove React/gateway/customer-service identity integration, deployment of the customer-service workload, an executed workload-to-Keycloak activity journey, durable production identity-event export, catalogue or order domain workflows, Redis or Kafka integration, Terraform-applied infrastructure, a retained Jenkins controller run, an operational observability stack, complete security gates, end-to-end customer journeys, production readiness, or high availability.
