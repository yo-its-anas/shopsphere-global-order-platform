# Requirements Traceability Matrix

This matrix maps examination requirements to implementation ownership, executable interfaces, evidence, demonstrations, and current status. Status is based on repository contents and validation performed against the current PoC environment; source code or a test definition alone is not treated as successful execution evidence.

## Status definitions

- **Foundation established** — a documented or executable skeleton exists, but domain behavior is absent.
- **Implemented** — executable source or configuration exists.
- **Platform-validated** — deployment or configuration checks have executed successfully, but the full user journey has not.
- **Functionally validated** — automated behavior tests have executed successfully for the stated boundary.
- **Planned** — no implementation evidence exists.

No Customer Identity and Account Management requirement is labelled complete. The retained integration report at `test-results/integration/customer-identity.xml` contains seven skipped tests, so it is collection evidence rather than end-to-end success evidence. Successful checks and unresolved evidence are recorded in the [Customer Identity validation record](evidence/customer-identity-validation.md).

## Current evidence boundary

The repository contains independently buildable services; customer profile, address, account-status, audit, and normalized activity APIs; React identity/customer screens; fixed API Gateway customer routes; an import-oriented Terraform baseline; and Kubernetes resources for PostgreSQL, Keycloak, and customer-service. Current live checks confirm the single kind node and those three workloads are Ready, internal-only services are used, PostgreSQL persistence is Bound, `customer_db`, `keycloak_db`, and `catalogue_db` exist with distinct owners, Keycloak realm/security/event-reader configuration is active, and customer-service health probes return HTTP 200. Frontend format, lint, 11 tests, and production build passed.

This evidence does not prove the complete browser → Keycloak → API Gateway → customer-service journey. API Gateway and frontend are not deployed in the cluster, customer-service tests did not complete during this review, and the retained integration JUnit report records seven skipped tests. It also does not prove SMTP password recovery, verified email, MFA, durable identity-event export, production rate limiting, Terraform-applied infrastructure, a retained Jenkins controller run, production readiness, or any form of host-level high availability.
