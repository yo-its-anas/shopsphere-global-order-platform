# Requirements Traceability Matrix

This matrix maps examination requirements to implementation ownership, executable interfaces, evidence, demonstrations, and current status. Status is based on repository contents and validation performed against the current PoC environment; source code or a test definition alone is not treated as successful execution evidence.

## Status definitions

- **Foundation established** — a documented or executable skeleton exists, but domain behavior is absent.
- **Implemented** — executable source or configuration exists.
- **Unit Validated** — isolated backend or frontend behavior tests executed successfully.
- **Integration Validated** — the specifically stated multi-component flow executed successfully.
- **Platform Validated** — deployment, manifest, dependency or configuration checks executed successfully, but the full user journey has not necessarily run.
- **End-to-End Validated** — an authenticated user-facing flow executed through its real application boundaries.
- **Pending / Not Verified** — implementation may exist, but no successful evidence exists for the stated boundary.
- **Planned** — no implementation evidence exists.

No Customer Identity and Account Management requirement is labelled complete. The retained integration report at `test-results/integration/customer-identity.xml` contains seven skipped tests, so it is collection evidence rather than end-to-end success evidence. Successful checks and unresolved evidence are recorded in the [Customer Identity validation record](evidence/customer-identity-validation.md).

For Product Catalogue and Inventory, **Unit Validated** means the 48-test
catalogue-service suite executed successfully. **Platform Validated** means the relevant
manifests and current internal workloads were checked; it does not prove the user
workflow. The focused React suite executed six tests. The explicitly enabled catalogue
